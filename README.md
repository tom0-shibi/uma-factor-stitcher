# ウマ娘 因子一覧メーカー

親・祖の因子を1枚の画像に。

Phase A「Stitch Core」のプロトタイプです。ブラウザ内でスクリーンショットを比較し、確定した縦方向の重複だけを除去してプレビューします。画像を外部へ送信しません。

## 起動・利用

このディレクトリで `python3 -m http.server 8765 --bind 127.0.0.1` を実行し、`http://127.0.0.1:8765/` を開いてください。VS Code Live Serverでも利用できます。ES Modulesを使うため、HTMLファイルの直接オープンではなくHTTPで配信してください。ビルドや依存パッケージのインストールは不要です。

1. PNG / JPEG / WebPを複数選択、ドロップ、または Ctrl / Cmd + V で追加します。
2. 入力環境を選び、必要なら上下ボタンで並べ替えます。同じ画像も別の登録として追加できます。
3. 「重複を解析してプレビュー」を押します。
4. 接続ごとの「確定」「要確認」「未解決」とプレビューを確認します。
5. 自動順序候補を使う場合は、候補の適用ボタンで並べ替えて再解析します。自動では登録順を変更しません。

「要確認」「未解決」の接続は元画像全体を残します。画像は捨てませんが、その箇所では重複が残ります。接続一覧にはプレビュー内部での結合位置をpxで表示します。折りたたみDebugで全ペアのスコア、候補差、信頼度、領域と最終順序を確認できます。

## 重複検出方式

- `region-detector.js` を解析・結合処理から分離しています。Phase Aでは全画像領域を使う安全側のfallbackです。環境選択は記録しますが、自動環境判定やSteam / DMM / GPG専用cropは行いません。
- 原画像を維持し、解析用に横72px・縦最大1000pxの輝度グリッドを作ります。左右約20%ずつを比較から除外し、中央の共通範囲を使います。
- Aの下側とBの上側について縦方向の全offset候補を探索し、輝度差と縦方向の変化の差を比較します。
- 上位候補の周辺を元画像の縦方向の画素単位で再探索します。別ピークのsecond-bestも保持し、bestとのスコア差、縦方向の特徴量、一致しない行の割合を判断材料にします。`confidence` は暫定的な指標であり、確率ではありません。
- 類似度・候補差・特徴量が十分で、下方向へ内容が続く接続だけを `confirmed` にします。重複画像・包含画像・曖昧な繰り返しは自動で削りません。閾値は `DEFAULT_OPTIONS` に集約しています。
- 各画像を開始点に試し、確定接続の強いものを順に選ぶ単純な探索で順序を提案します。切れた接続は登録順で補い、全画像を残します。最適解を保証する方式ではありません。
- Canvas描画は元画像から1:1で行います。解析用縮小画像を完成画像に使わず、確定接続だけ次画像の上側を切り取ります。

## 最小テスト

Node.js 22以降で `node --test tests/core.test.mjs`（または `npm test`）。npm依存パッケージはありません。

6件のテストで以下を確認します。

- 既知の重複、3枚の順序候補、期待する結合高さ
- 無関係・単色・周期模様・逆順・同一画像を無理に確定しない
- 異なる画像幅で全画像を残すこと、Canvas上限のエラー
- paste listenerの再登録でも1イベント1回だけ処理し、意図した再貼り付けを許容
- 選択・dropの登録順、同名画像の並べ替えと削除、不正形式の拒否
- 縮小グリッドでは表せない奇数pxの接続位置を元の画素単位へ補正

初回実装時の追加オフライン検証では、一時生成した720×1200のPNG / JPEG / WebPとローカルCanvasライブラリを使用しました。接続offset 503px、重複697px、3枚の結合高さ2206pxを確認し、PNG / lossless WebPの結合結果は全画素で期待画像と一致しました。この補助検証のライブラリや画像は製品の依存関係・リポジトリには追加していません。

HTTPでのページ配信は200応答を確認済みです。初回実装時、Codexのブラウザ操作は管理ポリシー検証のエラーで拒否されたため、実ブラウザでの初期化・コンソール・実操作・PC/スマホ表示は未確認です。上記ローカルテストはブラウザ検証の代わりにはなりません。

ブラウザ確認では、複数ファイル選択、同一画像の再追加、drop、2回の貼り付け、削除、上下移動、環境変更後の再解析、自動順序の適用を確認してください。開発者ツールで初期化エラーがないこと、未確定接続で画像が欠落しないこと、スマホ幅でも操作できることを確認してください。

## 既知の制限

- 実際のゲーム画像で未調整です。確定表示でもプレビューを目視確認してください。
- 固定ヘッダー・フッター・ウィンドウ枠を自動除去しません。固定UIや中央領域と異なる端の内容、圧縮・アニメーション・横ずれで誤判定や未確定が起こり得ます。
- 画像幅または解析倍率が異なるペアは未解決にします。結合時は拡大縮小せず中央に配置します。
- 比較対象はAの末尾からBの先頭へ続く縦スクロールです。小さい重複（解析12行未満、または短い画像の15%未満）、包含、逆方向、部分的なUI変化には弱い方式です。
- 同一画像を意図的に複数登録できますが、自動で捨てず「要確認」として残します。
- 通常3～10枚を想定した全ペア比較で、枚数に対し処理量は二乗で増えます。比較ペア間では画面操作へ処理を戻しますが、画像のdecode・解析やCanvas描画で一時的に重くなる場合があります。
- 結合Canvasは各辺32767px・6400万画素を安全上限としており、超える場合は明示的にエラーにします。端末によっては、それより小さな画像でもメモリ制約があります。
