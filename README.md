# ウマ娘 因子一覧メーカー

親・祖の因子を1枚の画像に。Phase A「Stitch Core」のプロトタイプです。画像は端末内で解析し、画像を外部へ送信しません。HTML / CSS / browser-native ES Modulesで動作し、ビルド・製品依存パッケージのインストールは不要です。

## 起動・利用

このディレクトリで `python3 -m http.server 8765 --bind 127.0.0.1` を実行し、`http://127.0.0.1:8765/` を開きます。VS Code Live Serverも利用できます。ES Modulesを使うためHTTPで配信してください。

1. PNG / JPEG / WebPを複数選択、ドロップ、またはCtrl / Cmd + Vで追加します。同じ画像も別登録として追加できます。
2. 「重複を解析してプレビュー」を押します。通常は画像の接続から自動で順序を推定し、その順にカードとプレビューを表示します。
3. 各接続の「確定」「要確認」「未解決」とプレビューを確認します。同一・ほぼ同一画像は独立した重複候補として残します。
4. 必要な場合だけ「詳細・救済用：手動で順序を指定」を開き、登録順を使うチェックを有効にします。カードの上下ボタンで並べ替えて再解析できます。
5. Debug欄の「ログをコピー」で概要と採用した接続をコピーできます。成功・失敗はボタン横に表示します。全候補ペアは別の「完全ログ」に保持します。

小型サムネイルは固定領域へ収め、管理カードを画面幅に応じて横並び・折り返しで表示します。通常のカードはサムネイル・ファイル名・サイズ・削除が中心です。

## 検出・結合方式

- `region-detector.js` は同じ解像度の複数画像について、同じY位置の輝度変動を比較します。変動の少ない固定UIと、変動が連続する帯を分け、スクロール領域を推定します。短い空白は画像高に対する比率で接続し、複数の強い帯が競合する場合は推定を見送ります。fixture固有の解像度・座標・カードサイズは使いません。
- 単一画像、同一画像だけ、判別材料が不足するケースは画像全体fallbackを維持します。入力環境は記録しますが、Steam / DMM / GPG専用cropはありません。
- duplicate判定は全画像の小さな輝度グリッドで行い、同一・ほぼ同一の場合は `kind: duplicate / offsetY: 0` とします。自動削除や通常のscroll接続には使いません。
- scroll判定では、検出した領域の中央約60%を比較します。Aの下側とBの上側を対応付ける正のtranslationを探索し、輝度差に加えて文字・カード・アイコンの縦横の勾配差を評価します。
- 複数ピークを元画像の縦方向の画素単位で再探索します。解析用の縦方向平滑化は横縮小のサンプリング幅に合わせ、サブピクセル移動・縮小による誤差を抑えます。元画像は変更しません。
- best / second-bestの差、局所特徴量、類似度を使い、十分なものだけ確定します。暫定基準は `DEFAULT_OPTIONS` に集約しており、confidenceは校正済み確率ではありません。
- 自動順序は各画像を開始点に試し、score・confidence・offset・overlap長・候補差から強い有向接続を順に選びます。要確認も順序の材料にしますが、要確認を確定へ昇格したり、重複除去の許可として使ったりしません。画像名・Ground Truth・登録順を正解にはしません。証拠のない同点は登録順で保持し、最適解や常に正しい順序を保証しません。
- 全画像に共通のスクロール領域を検出できた場合、先頭ヘッダー・末尾フッターを各1回だけ残します。確定接続だけ重複を除去し、要確認・未解決ではスクロール内容をそのまま残します。
- 最終Canvasは元画像の整数画素位置から1:1で描画します。解析用グリッドや加工画像は出力に使いません。

## Debug / 実画像fixture

「画像を追加」の折りたたみ「開発用：実画像Debug Fixture」から、提供画像8枚を一括登録できます。全8枚の取得・decode成功時だけ置換し、失敗時は既存登録を保持します。通常のFileを生成して、通常入力と共通のdecode・解析・結合処理へ渡します。

画像・Ground Truth・観測ログは [tests/fixtures/continuous-scroll](tests/fixtures/continuous-scroll/README.md) にあります。受領した669×892のJPEGをそのまま保持し、1029×1372へ拡大していません。Ground Truthは順序と枚数だけで、join offsetは未確定です。

通常のDebugログはframe概要、領域推定の根拠、選択接続と採否、overlapHeight / offsetY / score / secondBestScore / confidence / status、入力順・推定順・最終順を含みます。8枚では25行です。全56ペアはコピー対象に含めません。

## 関連テスト

Node.js 22以降で `node --test tests/core.test.mjs tests/fixture-input.test.mjs tests/region-and-debug.test.mjs`、または `npm test`。16件の関連テストが通過しています。Node標準機能だけを使います。

- 既知の重複、順序、元画素への補正、期待する結合高さ
- 無関係・単色・周期模様・逆順・同一画像を無理にscroll確定しない
- 幅不一致・Canvas上限、入力順・移動・削除、paste listener重複防止
- fixtureの順序・ファイルハッシュ・取得失敗・manifest検査
- 複数の解像度・縦横比で、固定UIと動く帯を分ける合成画像テスト
- TEST-1: 同一/near-identical画像のduplicate・offset 0
- TEST-2: 正のscroll offsetと固定UIを1回にした描画計画
- TEST-3: 固定UIが共通でもoffset 0/full-heightのscroll接続にしない
- 短いDebugログ、クリップボード成功/失敗の表示

HTTP配信した [tests/fixture-check.html](tests/fixture-check.html) のボタンから、実画像のLevel 1〜3を通常モジュールで再現できます。ファイル名を伏せて入力を混ぜ、さらに逆順でも検証します。GTは結果の照合だけに使用します。

今回の実画像確認は、既存のローカルCanvas実装でブラウザImage/Canvas APIを補うオフライン実行です。Level 1〜3はPASSで、接続offsetは302 / 288 / 280 / 285 / 282 / 279 / 284px。6接続が確定、先頭の1接続は要確認です。プレビューは669×2961となり、先頭接続の69px相当は意図的に残しています。これらは観測値であってGTではありません。

同じローカルDOM/Canvasアダプターで、実際のappモジュールのfixture置換・失敗時保持・手動救済から自動順序への復帰・25行ログのコピー経路も確認しました。画像ファイルと通常モジュールを使う検証であり、実ブラウザ確認ではありません。

## 未確認・既知の制限

- Level 4（ユーザーの実ブラウザでのプレビュー目視確認）は未完了です。先頭の要確認箇所に部分的な重複が残ります。
- Codexのブラウザ操作は管理ポリシー検証エラーで拒否されているため、実ブラウザのPC/スマホ表示・実クリップボード権限を含む操作確認は未実施です。ローカルのアダプターテストを実ブラウザ確認の代わりとはしません。
- 実画像はこの1セットだけです。別端末・PC・別レイアウトでの成功を保証しません。
- 時間変化を使うため、動画的な背景変化や複数の可動パネルでは領域を誤推定する場合があります。特定できない場合は全体fallbackとなり、精度が落ちます。
- 同じ解像度のグループ内で領域を推定し、画像幅や解析倍率が異なるペアは未解決です。画像間の拡大縮小・横方向の位置合わせはしません。
- 小さすぎる重複、非常に滑らかな画面、包含・周期模様・圧縮・動く装飾には弱く、確定表示でも目視確認が必要です。
- 通常3〜10枚を想定した全ペア比較です。ペア間では操作へ処理を戻しますが、decode・領域解析・Canvas描画では一時的に重くなる場合があります。
- Canvasは各辺32767px・6400万画素を上限とし、端末のメモリ制約によりさらに小さな画像でも失敗する場合があります。

## 対象外

OCR、動画、character segmentation、factor metadata、FactorSet、share renderer、Factor Checker連携、3列レイアウト、最終PNG export、SNS投稿、QRコード、cloud/server処理、Phase B/Cは実装しません。mainへのmergeはユーザーのブラウザ確認・明示承認後です。
